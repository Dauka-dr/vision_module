# Датасет: 11 классов действий

Пока только структура — данных нет.

## Структура

```
dataset/
├── label_map.txt          индекс класса → слаг → русское название
├── raw/<класс>/           исходные видеоклипы (что снимаете)
├── skeletons/<класс>/     извлечённые скелеты .npy, форма (T, 17, 3)
├── splits/                train.txt / val.txt / test.txt
└── annotations/           собранный .pkl для обучения в mmaction2
```

Поток данных: `raw/` → (RTMDet+RTMPose из `pipeline.py`) → `skeletons/` →
(сборка) → `annotations/` → обучение.

## Что учесть при съёмке

**Классы 2 и 3 по одному скелету почти неразличимы.** Поза «голова опущена, руки
перед собой» одинакова и для телефона, и для тетради, и для ноутбука. Модель на
скелетах их будет путать. Варианты: либо принять путаницу, либо добавить второй
поток — RTMDet уже умеет детектить `cell phone`, `book`, `laptop` (это штатные
классы COCO), и объединять «поза + объект рядом с руками». Решать до массового
сбора, потому что это влияет на то, что именно снимать.

**Ракурс камеры должен совпадать с боевым.** Скелетные модели чувствительны к
смене ракурса. Снимайте с той же высоты и того же угла, где будет стоять реальная
камера, иначе модель просядет при переносе.

**Классы 7–10 (стоит/идёт/бежит) снимаются в другой обстановке** — в аудитории
сидящих людей их почти не будет. Логично снимать в коридоре, и это нормально:
эти классы различаются динамикой, а не окружением.

**Класс 10 (`11_fighting`)** — самый чувствительный юридически. Ложное
срабатывание здесь дороже, чем в остальных классах. Стоит заранее решить, будет
ли он вообще влиять на какие-либо решения или только на уведомление человеку.

**Баланс классов.** Не снимайте 500 клипов «сидит» и 20 «поднимает руку» —
редкие классы модель просто проигнорирует. Ориентир на пилот: **100–300 клипов
по 3–5 секунд на класс**, примерно поровну.

**Разнообразие людей.** Разная одежда, телосложение, рост, посадка. Модель,
обученная на пяти одинаково одетых волонтёрах, не перенесётся на аудиторию.

## Правовая сторона

Для этапа сбора данных — снимайте волонтёров с их согласия, не реальные занятия.
Это снимает вопрос об основании обработки на время R&D. Перед эксплуатацией на
реальных студентах нужно согласование с юротделом (основание обработки
персональных данных, оценка воздействия, политика хранения и доступа).

## Соглашение об именовании клипов

```
<класс>_<съёмка>_<человек>_<номер>.mp4
например: 02_sleeping_s01_p03_007.mp4
```

`съёмка` и `человек` нужны, чтобы делить train/val **по людям**, а не случайно:
если один и тот же человек попадёт и в train, и в val, метрика будет завышенной.
